About PhishShield

A functional college project bridging Java Object-Oriented Programming (OOP) and Database Management Systems (DBMS).

1. What is Phishing and How PhishShield Works

Phishing is a form of social engineering where attackers deceive users into visiting fraudulent websites designed to steal credentials, personal data, or session cookies. Most phishing attacks originate via deceptive links distributed through email, SMS (smishing), or instant messaging.

PhishShield analyzes the structural and lexical characteristics of submitted URLs using a static, rule-based heuristic detection engine.

Crucial Security Principle: PhishShield never visits, fetches, or establishes a network connection to submitted URLs. Analysis is performed purely in-memory using Java lexical analysis.

2. Heuristic Detection Rules & Risk Scoring

PhishShield evaluates five core structural indicators, each assigned a weighted risk score:

  • Unusually Long URL (+10 pts): Detects URLs exceeding 75 characters. Phishers use bloated URLs to pack encoded redirect destinations and push actual domains out of browser view.
  • IP Address as Hostname (+25 pts): Detects raw IPv4 or IPv6 numerical addresses used instead of registered domain names. Attackers use this to evade domain registrar vetting.
  • Suspicious Keyword Combinations (+10 pts): Flags URLs containing credential-harvesting keywords (e.g. login, verify, account, security) especially when paired with high-value brands (paypal, apple, chase).
  • Unusual Subdomain Structure (+15 pts): Flags deep subdomain nesting (>2 dots) or brand names embedded inside subdomains (e.g., paypal.com.evil-portal.net).
  • Misleading URL Structure (+20 pts): Detects deceptive syntaxes such as the @ credential trick, abnormal ports (e.g. :8080, :8443), excessive domain hyphenation, or double slashes in paths.

Risk Classifications: The cumulative score is capped at 100 and classified as:

  • 0 – 19: Low Risk Standard vigilance recommended.
  • 20 – 49: Suspicious Multiple warning indicators found. Proceed with caution.
  • 50 – 100: High Risk Strong structural indicators of phishing. Avoid interacting.

3. Java OOP Implementation (College Viva Summary)

PhishShield is engineered to demonstrate the four pillars of Object-Oriented Programming:

Encapsulation

Classes like URL.java, Scan.java, and Finding.java encapsulate internal state using private member variables. Access and modification are mediated exclusively through validated constructors, getters, and setters.

Abstraction

The detection architecture separates interface from implementation. The interface DetectionRule.java defines the contract (evaluate(URL)), while BaseDetectionRule.java provides shared abstract functionality.

Inheritance

Concrete detection rules (LongURLRule, IPAddressRule, SuspiciousKeywordRule, SubdomainRule, URLStructureRule) inherit shared state and utility methods from BaseDetectionRule.

Polymorphism

URLAnalyzer.java manages an ArrayList<DetectionRule> collection. At runtime, it loops through each rule polymorphically calling rule.evaluate(url) without knowing the concrete class type.

Exception Handling & Collections

Custom exceptions (InvalidUrlException, DatabaseOperationException, UrlNotFoundException) are intercepted by GlobalExceptionHandler.java. Collections like ArrayList, LinkedHashSet, and Map are used for clean data structures.

4. MySQL Database Schema (DBMS Summary)

The application interacts with MySQL 8 (phishshield_db) using Spring JdbcTemplate and transactions:

  • URL_MASTER: Stores unique URLs. Columns: url_id (PK), original_url, normalized_url (UNIQUE), latest_score, latest_status, first_seen, last_seen, total_scans.
  • SCAN_HISTORY: Stores every scan event. Columns: scan_id (PK), url_id (FK), scanned_url, scan_score, scan_status, scanned_at.
  • SCAN_FINDINGS: Stores individual warning signs per scan. Columns: finding_id (PK), scan_id (FK), rule_name, points, explanation.

DBMS Concepts Implemented: Parameterized queries (SQL injection prevention), Foreign Key referential integrity with cascading deletes, Indexing for sub-millisecond retrieval, JOIN operations combining scan history with URL stats, aggregate COUNT queries, and GROUP BY analytics.
